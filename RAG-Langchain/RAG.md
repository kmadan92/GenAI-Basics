# Advanced RAG Techniques

This document explains five advanced techniques to improve Retrieval-Augmented Generation (RAG) pipelines. These methods enhance retrieval accuracy, coverage, and reasoning capabilities by combining semantic and lexical search with LLM-powered query handling.

---

## 1. Fan-out Retrieval (Hybrid Retrieval)

**What it is:**  
A method that sends a single user query to multiple retrievers—typically a semantic vector retriever (e.g., Qdrant) and a lexical keyword retriever (e.g., BM25)—and merges their results.

**Why use it:**  
- Different retrievers excel at different match types (semantic meaning vs. exact keywords).  
- Combining them improves recall and coverage.

**How it works:**  
- Query is issued to all retrievers in parallel.  
- Results are merged and deduplicated.  
- The combined context is passed to the generation model.

---

## 2. Reciprocal Rank Fusion (RRF)

**What it is:**  
A simple yet effective technique to combine ranked result lists from multiple retrievers into a single fused ranking.

**Why use it:**  
- Balances the influence of each retriever’s ranking.  
- Mitigates dominance by any single retriever with strong outlier scores.

**How it works:**  
- Assigns scores to each document based on rank using:  
  `score = 1 / (k + rank)`, where `k` is usually 60.  
- Scores are summed across retrievers for the same document.  
- Documents are sorted by total score for final ranking.

---

## 3. Query Decomposition

**What it is:**  
Splitting complex or compound user queries into simpler, focused sub-questions.

**Why use it:**  
- Complex queries may fail to retrieve all relevant information as a single query.  
- Simpler sub-questions improve retrieval precision and recall.

**How it works:**  
- An LLM generates 2–4 sub-questions from the original query.  
- Each sub-question is used to retrieve documents independently.  
- Retrieved documents are combined for answer generation.

---

## 4. Chained Question Answering (Chained QA)

**What it is:**  
An extension of query decomposition where the answer to one sub-question is passed as context to the next, enabling multi-step reasoning.

**Why use it:**  
- Useful for multi-hop questions where later answers depend on earlier ones.  
- Allows sequential, context-aware answering.

**How it works:**  
- Decompose the query into a chain of sub-questions.  
- Answer the first sub-question with retrieval and generation.  
- Use the generated answer as additional context for the next sub-question.  
- Repeat for subsequent sub-questions.  
- Aggregate final answers.

---

## 5. HyDE (Hypothetical Document Embeddings)

**What it is:**  
Embedding the **hypothetical answer** generated by an LLM instead of embedding the raw query to improve semantic retrieval.

**Why use it:**  
- Provides richer semantic signals than raw queries.  
- Especially effective for vague or short queries.

**How it works:**  
- Generate a pseudo-answer for the query using an LLM.  
- Embed this pseudo-answer using your embedding model.  
- Use the embedding for vector search.  
- Combine with other retrieval results as usual.
